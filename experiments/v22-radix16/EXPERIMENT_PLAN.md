# RUNE v22 — Four-pass 16-bit stable LSD radix experiment

**Pre-registered state:** SPECIFIED, unverified, HOLD MERGE. Parent is v20 diagnostic source+evidence `d172516a691d82914b432a8d22bbaef55d828f91`. Excludes v21 NO-GO MSD-local sorting and v18 buffering, which are not revived.

**Proposed mechanism:** A 64-bit key can be stably sorted by four LSD digits of sixteen bits each, using 65,536 counters/positions per pass instead of the frozen v17 eight 8-bit passes. This halves global scatter passes at the cost of a much larger counter working set. Two independently falsifiable experimental workers: `fused16` accumulates all four digit histograms in one scan (1 MiB of uint32 counters); `perpass16` builds one 256 KiB histogram per pass (four input count scans). Both fall back exactly to frozen 8-pass worker if `n>UINT32_MAX`. All offsets and counts are exact for `n<=UINT32_MAX`.

**Correctness invariants:** four 16-bit digits cover all 64 bits and every scatter is stable, so unsigned numeric ascending output is exact, including empty, duplicate, UINT64_MAX, narrow-domain and sparse-domain values. Work O(4n+4*65536) fused / O(8n+4*65536) perpass; O(n+4*65536) / O(n+65536) scratch. These are conventional radix mechanisms with extensive prior art, not original algorithm claims.

**Empirical target:** Compare six algorithms on identical input (RUNE17 full, RUNE17 raw fixed8, both candidate versions, pinned original Highway VQSort and sequential IPS4o). x86 EPYC 7763 and ARM Neoverse-N2 GitHub Actions runners; N=1M and N=4M, five fixed seeds, five workloads (uniform64 primary, random32, K85,000, sorted, alternating controls), one warmup plus three timed measurements with randomized order. Full independent std::sort oracle on every output; six × five × five × two × two = **600 exact measured algorithm rows**. Additional native and ASan/UBSan differential arrays both architectures. Raw per-seed times and machine provenance archived.

**Decision locked before data:** NO-GO for integration unless the candidate materially beats *both* frozen v17 raw worker and pinned Highway VQSort on x86 4M uniform64 across all five held-out seeds, with no major ARM regression. Even a win remains a research-only conditional GO until new held-out builds/CPUs and production-dispatch trials. No artificial promotion through sorted-input or two-value controls, where the existing dispatcher already has special cases. No prior scientific novelty/SOTA assumption.
